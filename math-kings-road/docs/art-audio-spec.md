# 《山林算術勇者》第一大關美術與音效規格

## 1. 創作方向

- **對象**：國小三至四年級；資訊要一眼可讀，角色表情清楚，不使用驚悚、血腥或過強閃光。
- **核心風格**：原創 16-bit 台灣山林奇幻 RPG。以紅檜、月桃、蕨類、雲海、石階與紙燈為視覺語彙，採回合制 JRPG 的清楚站位與選單節奏，但不仿製既有作品的角色輪廓、怪物、介面、標誌、配樂或招牌音型。
- **畫面比例**：以 16:9、1280×720 為設計基準；像素素材使用最近鄰縮放，基礎格 16×16，角色以 48×48 或 64×64 製作。
- **可讀性**：題目與三個選項永遠是最高對比層；正文至少 20px，按鈕至少 48px 高。顏色之外再以圖示、文字和形狀表達正誤。

| 用途 | 色票 | 備註 |
| --- | --- | --- |
| 夜山背景 | `#102C2A`、`#1B4640` | 深色但不純黑 |
| 林葉主色 | `#3D7A45`、`#76B852` | 主角與成功狀態 |
| 雲霧 | `#D8EFE8` | 面板與遠景 |

| 日光金 | `#F5C451` | 葉幣、可互動焦點 |
| 答對 | `#56C271` | 搭配勾號與上升粒子 |

標題建議使用可合法內嵌的圓體像素字或系統粗體；數字、乘除符號與分數線必須清楚，避免裝飾字型。若無字型資產，優先使用 `system-ui, "Noto Sans TC", sans-serif`。

## 3. 第一大關：霧林算術道

### 場景節奏

| 小關 | 場景變化 | 敵人概念 | 教學／演出重點 |
| --- | --- | --- | --- |
| 1 | 晨光林口 | 葉芽史萊姆 | 第一次選答案與攻擊 |
| 2 | 蕨葉小徑 | 松果小兵 | 金幣提示 |
| 3 | 溪邊踏石 | 溪石龜 | 裝備防禦提示 |
| 4 | 月桃花坡 | 花粉精 | 道具提示 |
| 5 | 雲霧木橋 | 霧球怪 | 中段難度上升 |
| 6 | 紅檜樹洞 | 菇燈怪 | 題型換場提示 |
| 7 | 螢火林 | 夜翅蛾 | 暗景高對比測試 |
| 8 | 古石階 | 石紋守衛 | 敵人耐久提高 |
| 9 | 山神門前 | 雲角獸 | 魔王前預告 |
| 10 | 雲海祭壇 | 魔王「百題山魈」 | 三段表情、勝利演出 |

每小關戰鬥勝利後播放 1.2–1.8 秒前進動畫：敵人化成葉光 → 主角向右跑三步 → 背景視差滑動 → 關卡旗標亮起 → 進商店。玩家點擊可略過，但不應略過獎勵結算。

### 角色與敵人

- **主角**：「小芽勇者」，斗笠上有嫩芽，短披風與木劍；剪影呈三角斗笠＋短劍，避免與任何既有 RPG 勇者服裝相似。
- **夥伴**：「算算鳥」，原創圓腹小鳥，負責教學與提示，不直接代答。
- **普通敵人**：圓潤、兩到三個主要色塊、最多一個小道具；受擊只後退與閃白，不出現傷口。
- **魔王**：「百題山魈」為石木混合的山林守護靈，角像分岔樹枝、胸口有十格算盤紋。不可採用真實保育類動物作為被擊打的敵人。
- **動畫幀**：待機 4 幀、攻擊 6 幀、受擊 2 幀、勝利 6 幀；8–12 fps，程式可控制停格以保留像素感。

## 4. 戰鬥介面

1. 上半部為山林戰場：敵人右側、主角左側；HP 條同時顯示數值。
2. 下半部為題目木牌，三個答案為等寬大按鈕，順序每題可洗牌。
3. 選取後先鎖定三個選項：答對顯示勾號和解題短句，再播放主角攻擊；答錯顯示叉號、正確概念提示，再播放敵方攻擊。
4. 鍵盤焦點使用金色 3px 外框；按鈕具有按下位移 2px 的像素回饋。
5. 動畫中的題目仍須可被輔助技術讀取；重要回饋使用 `aria-live="polite"`。
6. 提供「音效」、「減少動態」與「跳過前進動畫」設定。減少動態時以 200ms 淡入淡出取代震動、視差和大量粒子。

## 5. 商店與道具美術

## 6. 戰鬥特效

| 事件 | 動畫 | 時長 | 粒子上限 |
| --- | --- | ---: | ---: |
| 選項點擊 | 按鈕下壓＋小光點 | 80ms | 2 |
| 答對 | 綠色勾號、3 顆方形葉光上升 | 350ms | 3 |
| 主角攻擊 | 米白弧形斬線、敵人後退 4px | 420ms | 5 |
| 答錯 | 橘紅叉號、題卡輕晃 2 次 | 300ms | 0 |
| 主角受擊 | 白色閃格 1 次、後退 3px | 280ms | 3 |
| 魔王登場 | 紫色霧圈收束、算盤紋逐格亮起 | 900ms | 8 |
| 勝利 | 金色葉片、關卡旗標點亮 | 1100ms | 12 |
| 購買 | 兩枚葉幣縮進錢箱 | 360ms | 2 |

禁止快速全螢幕閃爍；單次白閃不超過 100ms。手機低效能模式將粒子減半，避免特效影響作答。

## 7. 音效規格與程式對照

`app/game/audio.ts` 以 Web Audio 即時合成，不下載音檔。所有音效短促、無人聲，主音量預設 45%。

| Key | 使用時機 | 聲音性格 |
| --- | --- | --- |
| `click` | 選項、選單 | 短方波木鈕感 |
| `attack` | 玩家出招 | 向下掃頻＋短噪音斬擊 |
| `hit` | 角色受擊 | 低頻方波＋鈍噪音 |
| `correct` | 答對確認 | 三音上行琶音 |
| `wrong` | 答錯確認 | 三音下行，不做刺耳蜂鳴 |
| `victory` | 小關／魔王勝利 | 六音短勝利句，為原創通用音列 |
| `buy` | 購買成功 | 兩顆清亮硬幣音 |
| `boss` | 魔王登場 | 低音脈衝與低通風聲 |

建議事件順序：答對時 `correct` → 180ms → `attack`；答錯時 `wrong` → 220ms → `hit`；魔王關進場先 `boss`，進場演出結束後才顯示可作答選項。不要讓同類音效在 100ms 內重疊播放。

客戶端用法：

```ts
import { gameAudio } from "@/app/game/audio";

void gameAudio.play("correct");
gameAudio.setMuted(true);
gameAudio.setVolume(0.35);
// 僅在確定整個遊戲音效系統不再使用時呼叫：
gameAudio.dispose();
```

## 8. 交付與驗收

- 素材命名採 `角色-動作-方向-序號`，例如 `hero-attack-right-03.png`；正式素材應附來源與授權紀錄。
- 以 100%、200%、300% 最近鄰縮放檢查像素邊緣；深色與明亮場景都要檢查題目對比。
- 音效在 Chrome、Edge、Safari 行動版實機測試；未經使用者互動前不建立／播放 AudioContext。
- 靜音後不得殘留尾音；重新開啟可正常播放；離開遊戲呼叫 `dispose()` 後無持續音訊資源。
- 連續快速點擊、切換頁籤、低電量模式與「減少動態」開啟時，題目按鈕仍可操作且不重複結算。
- 每個正式角色、圖示與音型均需通過「無既有角色／標誌／招牌旋律相似性」人工檢查。
