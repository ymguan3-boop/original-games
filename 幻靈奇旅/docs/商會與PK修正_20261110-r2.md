# 商會體驗與 PK 中繼修正

- 商會進入時保留完整載入遮罩，等待場景角色、模型、貼圖及圖片解碼後才開放操作；失敗時可重試或僅重置商會。
- `firstlight_shop_v1` 舊資料在本次版號首次啟動時備份為 `firstlight_shop_v1.before-compact-20261110-r2`，再初始化商會。使用 `firstlight-shop-reset-version` 避免後續進入反覆重置。不刪除初光鎮、守護戰、圖鑑或共用解鎖資料。
- 教學保留所有管理按鈕並淡化非目標按鈕；新增由玩家點擊「開始營業」的步驟，移除有貨架即自動營業的邏輯。
- Lv.1～5 長寬均乘以 `Math.SQRT1_2`，面積精確減半；櫃台、排隊保留格及員工巡查點依尺寸調整。Lv.6～10 維持 Lv.5 建築尺寸。
- 主角採與人形顧客一致的模型尺寸上限；保持原角色與服裝。
- 顧客先沿左側石板小路走至入口，生氣、事件及付款後皆保留原比例走至門口，再沿小路離開。移除逾時直接刪除及離店縮小動畫。
- 宣傳員移至入口外側、石板小路旁的指定方向，加入揮動傳單的演出。返回初光鎮放入頂部資訊列，與其他快捷按鈕共用樣式與手機換行規則。
- GPT 網站與 GitHub Pages 的守護戰預設使用 HTTPS 中繼，正式站同瀏覽器分頁也固定走 HTTPS；僅明確使用 ?pknet=local 的開發測試保留本機通道。中繼不需 UDP 或玩家間 WebRTC 直連，不修改使用者防火牆。四碼房號搭配每頁獨立隨機憑證，支援同帳號、同 IP。動作具唯一 ID 防重播，快照只保留最新一筆；離線逾時結束連線。
- 中繼實作為 `defense/server/pk-relay.js`，由既有 GPT Sites 的 `/api/pk` 路由接上 D1。該路由不修改原有登入與雲端存檔 API。其他任意自架網域未開放 CORS；現行 Sites 與 GitHub Pages 網域已列入。

程式驗證：商會 64/64、一般場景與新增驗收 40/40、守護戰 141/141。包含實際 SQLite 的兩端配對、卡組訊息、操作、最新戰況、第三人拒絕、訊息重試去重、離線通知與跨來源限制；並驗證商會只重置一次、保留其他存檔、載入完成閘門及手動營業。

正式網站已發布第 38 版。瀏覽器驗證商會手動開店、顧客進場、門外宣傳員與縮小後的排版；兩個網頁透過正式 HTTPS API 配對、交換卡組、雙方確認開戰、同步倒數，客端出擊的小熊亦出現在主端戰場。兩端未記錄 console error。截圖見本目錄下 verification-20261110-r2。實體跨裝置／不同電信網路與所有島嶼的完整遊玩未納入本次回歸。
