# Lv.3 廣場競價大戰（v57）

## 操作與相容性

Lv.3–5 在商會對面廣場點擊紅白棚地攤，或從「更多 → 廣場競價大戰」進入。Lv.1–2 不顯示。先營業並備妥實際庫存，每個營業日可完成一局；可不參加。

沿用使用者先前確認的直立式手機與低模風格，不重新開放橫式遊玩。2D、3D 共用 `plaza-auction.js`；不建立第二套商品資料或存檔。競價視窗開啟時暫停營業，關閉後恢復原有暫停狀態。每日訂單、目前回合與報價會自動儲存；放棄後再進入仍是同一筆每日訂單，不可重抽商品。

## 規則與參數

| 項目 | 設定 |
|---|---|
| 開放等級 | Lv.3；Lv.4–5 使用更積極的對手策略及較高預算 |
| 地攤常駐客流影響 | 原客流 × 0.92，不影響門口動線 |
| 每日局數／回合 | 完成一局；最多三回合，可提前決標 |
| 商品與數量 | 已解鎖、可販售且有可交貨庫存，1–4 件 |
| 報價限制 | 整數；不得低於向上取整的單位成本、不得高於預算 |
| 得標條件 | 玩家最終有效報價嚴格低於商販；同價商販得標 |
| 勝利 | 商品來客 +15～30%；該商品後續正毛利 +10～30%；即時訂單收入 |
| 失敗 | 商品來客 -15～30%；不扣款、不扣貨、不減售價 |
| 連敗讓價 | 每敗一次，對手較寬鬆策略機率 +10 個百分點；最多 +30；勝利歸零 |
| 生效時間 | 當日；跨日讀取會排除舊效果 |

全店客流影響依可供貨品類平均曝險計算，另以指定商品權重調整需求；總倍率設有上下界，不會讓商會完全沒有來客。其餘天氣、員工被動、事件、裝潢加成沿用原公式。實際勝率取決於報價、成本、預算與等級，並非宣稱任何報價固定增加 10% 勝率。

訂單先消耗倉庫，再扣未被顧客購物籃保留的架上商品；交貨前再次檢查庫存。收入、銷貨成本及銷量納入原帳本，使用唯一訂單 ID 防止重複入帳。購入時已付貨款，交貨不重扣採購款；銷貨成本採實際平均成本。競價訂單本身不享後續正毛利加成；加成不修改商品售價或成本，負毛利不發加成。

## 驗證

- 39 項相關測試通過，包含原有邀客進店、門口動線、職務疲勞、多商品貨架、補貨、限定武器與命運機會。
- 12,000 次 AI 報價模擬：固定成本 20／預算 80／玩家報價 48，Lv.3 在連敗 0／1／2／3 時勝率為 52.1／59.5／66.5／74.1%；Lv.5 為 40.9／50.5／58.7／68.3%。這是固定條件的測試結果，不是遊戲勝率承諾。
- 另 1,000 筆實際訂單結算模擬，472 勝／528 敗；收入 27,768 G，逐局檢查庫存、金額與成本。沒有讓訂單重複入帳或套用自身加成。
- 390×844 手機畫面，2D、3D 各一次實際滑鼠點擊攤位 → 調價 → 三回合 → 成功入帳；視窗未超出畫面，無瀏覽器程式錯誤。路人泡泡為 17px 深色 DOM 文字。
- 截圖與操作證據保留於工作區 `artifacts/nov14-auction-*`；正式發布另核對公開頁面。

## 美術狀態與限制

內建 imagegen 可用，環境未提供 IMAGEN；沒有冒稱以 IMAGEN 生成，也未安裝付費服務。此輪製作一個代表攤位及原有角色系統的程序模型，未批次擴展不同商販角色。3D 不是圖片看板，2D 使用透明圖與既有顧客 GIF、CSS 動畫。

技術驗證通過；新攤位細節仍可由玩家試玩後確認。未交付獨立 GLB、角色多視角設定集或逐格角色表情圖集；角色動作使用現有可關節控制的低模系統，非新製全套骨架。低階實機長時間耗電／幀率尚未量測，桌面無頭瀏覽器抽驗不等同所有手機效能保證。
