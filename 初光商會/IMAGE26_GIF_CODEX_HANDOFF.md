# 初光商會：image2.6 事件 GIF 重製與舊素材清理（Codex 交接）

> 此文件只涵蓋本次 GitHub MCP 無法直接呼叫 **image2.6 技能來批量生成二進位 GIF** 的部分。一般店面視角、頭頂事件互動、上方巡店按鈕、搖桿避讓與速度加倍已由程式修正，請在最新 main 基礎上繼續，不要退回舊版。

## 給 Codex 的執行指令

你已連接倉庫 `ymguan3-boop/original-games`。請在本機/雲端工作區尋找 image2.6 技能定義及可用的生圖模型；**只在技能確實存在時使用它**。若找不到，先回報缺少什麼工具，不要宣稱 GIF 已生成。請直接改動倉庫、提交 PR，不要只寫建議。

### 1. 圖檔來源及視覺一致性

- 先讀 `初光商會/js/funny-events.js`（24 種趣味事件）、`初光商會/js/core.js`（16 種原始事件）及 `初光商會/js/shop-operations.js`（缺貨、排隊、生氣等運營事件），以及現有 `初光商會/assets/`。
- 請參考商會**現有原創幻靈人物、員工與顧客的外觀**（不准擅自換角色或使用外部受著作權保護的其他遊戲人物）；保留卡通 3D、溫暖鄉村、清楚粗輪廓、誇張肢體動作。若無法取得某角色外觀，先以角色統一色系的簡單 Q 版替身，標註待確認。
- 圖像只放畫面動作，**不得在 GIF 中烙印中文文字**；事件名稱、處理方式、滿意度和熟練度維持使用 HTML 原生清晰文字，遵守既有情緒色系（開心綠、生氣紅、疑惑黃、疲勞灰紫、訓練藍、搞笑紫）。

### 2. 動畫生成規格

- 每一事件 **1 組獨立 GIF**，以 `初光商會/assets/event-gifs/v2/` 存放，檔名使用原事件 id：
  `event-1.gif` 至 `event-16.gif`；`comic-1.gif` 至 `comic-24.gif`；另有 `stockout.gif`、`queue-complaint.gif`。
- 每段 6–10 幀，1.2–2.5 秒，可無縫循環，建議原始作圖 512×512，輸出手機版 GIF 寬高 256×256；若難以同時保持清晰和檔案小，允許另存 animated WebP 作可選最佳化，但 **GIF 一定要存在**。
- 儘量透明背景，人物或物件不能出框；每個角色在所有幀的造型、比例、色系、視角和光源一致。避免快速閃黑、暴閃、刺眼光、劇烈鏡頭位移。
- 動作重點清晰（例如拍手、跺腳、甩尾、追逐、滑倒、泡泡彈起），盡量採 24~64 色調色盤，量化及壓縮後單檔目標低於 300 KB，超過請先壓縮再提交。製作過程中的參考圖、spritsheet、暫存草稿不要放進正式部署目錄。
- 請逐一檢查 GIF 有 2 幀以上、非全白/全透明、可循環播放，角色動作在每一幀連續且不破圖。

### 3. 分類分鏡（image2.6 提示詞綱要）

**收銀員：** 發票像圍巾旋轉、零錢長腳排隊逃跑、收銀機突然唱生日歌、樹果被拿來當找零。畫面不含硬幣數字及文字，夥伴臉部隨事件驚訝→努力解決→笑出來。

**補貨員：** 紙箱堆疊套娃、推車誇張甩尾、魔法貨架打噴嚏，箱子晃動但角色不受傷，最後恢復整齊。

**推銷員：** 客人把折扣誤認為折紙、試用魔法藥水變成明星大頭照、兩人退後撞出探戈舞步。角色動作豐富而不閃屏。

**鍛造師：** 鐵鎚打哈欠、鍛爐冒棉花糖雲、神劍磨成湯匙，保持安全童趣卡通效果。

**倉管員：** 箱子躲貓貓、盤點單摺紙飛機、庫房標籤長小鬍子。

**保全員：** 保全追自己的影子、把掃地機器人誤認成小偷、門口歡迎立牌敬禮。

**清潔員：** 拖把滑成花式溜冰、掃把追灰塵團、地板亮到可當鏡子。

**迎賓員：** 歡迎詞變饒舌、鞠躬後帽子飛起、與顧客比鬼臉。

**顧客疑惑／不滿：** 缺貨時低頭找商品→抬頭問號→攤手；排隊久了看向收銀→跺腳→冒紅色怒氣。生氣是短暫誇張喜劇，不要攻擊、暴力或歧視。

對於原有 16 種事件，請從 `eventNames` 讀取確切標題，各生成與事件**確切內容對應**的短動畫，不可只把相同角色模板複製 16 次充數。

### 4. 接入現有 UI（保持小視窗）

- 修改 `js/incident-sketch.js` 與 `js/patrol-panel.js`、`js/event-coach.js`，根據 `event.id` 透過明確資產對照表載入新 GIF（使用 `loading=lazy`，有可預測的檔案路徑），沒有新 GIF 時回退既有 CSS 動畫，不允許白屏。
- **每個事件動畫都在原本可拖曳／縮放的浮動視窗內播放**；不可建立全螢幕事件遮罩，不可擋住主要 3D 商店的操作。
- 舊的 `event-effects.css` 和 `event-responsive-v10.css` 中如有過時且已完全不用的 GIF 相關規則，再清理；**不要破壞**員工與顧客的頭頂情緒文字、滿意度浮字及事件名稱點擊。
- 避免每 0.5 秒重新建立 GIF DOM：`app.js` 原已有盡量維持主管事件面板節點的機制，請沿用。

### 5. 移除舊素材與驗證

- 先用全倉庫搜尋，產出 `asset-cleanup-report.md`，列出每個準備刪除的檔案，以及「全倉庫無引用」或「新檔已替代」的依據。
- 待新版 42 個 GIF 全部生成、引用、體積及播放測試通過後，再清理 `assets/event-gifs/` 舊版 10 個 GIF；不要刪除被其他 UI 引用的 `assets/ui-generated/icon-*.webp` 或任何夥伴、模型、Logo。
- 可刪除經全倉庫確認沒有引用的 `event-*.webp`、重複草稿、臨時幀圖片；**不要憑檔名猜測是否可刪**。
- 使用 Node 或 Playwright 驗證：一般／手機橫直畫面，40 種事件可按 id 預覽、不重複漏圖，無壞連結，角色事件名稱仍可點，手機能拖曳及縮放事件視窗；測試前後存檔與遊戲進度不被重置。
- 最後請提交 PR，附新 GIF 清冊、總容量、更新／刪除檔案清單、測試結果及 GitHub Pages 截圖。所有生成檔不得含 API 金鑰或私人資料。
